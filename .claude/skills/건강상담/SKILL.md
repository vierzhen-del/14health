# 건강상담 — 가족력·현재 치료·검진수치 종합 상담

## 절차

1. 대상 확인 후 상담 브리핑을 만든다 (관계호칭 생략 시 가족 전체):
   ```bash
   14health consult <관계호칭>
   ```
   MCP가 등록돼 있으면 `consult_briefing` 도구를 직접 호출해도 된다 —
   같은 내용을 구조화된 JSON으로 받는다.

   브리핑에 담기는 것: 나이·성별, 가족력(누가 앓았는지), 현재 치료중인
   질환·복약·다음 예약, 최근 검진 수치와 판정·추이, **교차 소견**
   (가족력 × 현재 치료 × 검진수치), 혈관나이, 검진 이행률, 추천 질문.

2. **브리핑을 읽고 상담한다.** 사용자의 질문에 답하되:
   - **수치·판정·교차 소견은 규칙 엔진 출력을 그대로 사용**하고 임의로
     바꾸거나 새로 계산하지 않는다. 해설·우선순위 정리·질문 다듬기가 역할이다.
   - 가장 시급한 것부터 말한다. 교차 소견의 심각도(2 → 1 → 0)가 이미
     정렬돼 있으니 그 순서를 존중한다.
   - "치료 중인데 수치가 안 잡힘"은 약을 바꾸라는 뜻이 아니라 **진료 때
     상의할 거리**라는 점을 분명히 한다.

3. 진료 예약이 잡혀 있으면 그 날짜에 맞춰 **물어볼 것을 정리**해준다.
   브리핑의 "이런 걸 물어보세요"를 출발점으로 쓰되, 사용자의 상황에 맞게
   다듬는다.

4. 상담 중 새로 알게 된 사실(치료 시작, 약 변경, 예약 등)은 저장을 제안한다:
   ```bash
   14health treatment add <관계호칭> --condition <질환> --status 치료중 --dept <진료과>
   14health treatment add <관계호칭> --med <약이름> --dose <용법> --for <질환>
   14health treatment add <관계호칭> --appointment <YYYY-MM-DD> --dept <진료과>
   ```

5. 마지막에 반드시 고지: **규칙 기반 참고 정보이며 의학적 진단이 아니다.**
   이상 소견은 의료진과 상담해야 한다.

## 규칙

- 브리핑에는 **수치가 들어 있다** — 상담에 필요하기 때문이다. 실명·주민번호·
  식별번호는 들어가지 않는다(저장 시점에 이미 제거됨).
- 이 내용은 vault와 이 대화에만 남긴다. **웹 검색이 필요하면 개인 수치를
  빼고** 일반 의학 지식만 검색한다.
- 진단명을 새로 붙이거나 약을 추천하지 않는다. "이건 ~일 수 있으니 의사에게
  물어보라"까지가 범위다.
- 사용자가 불안해하면 절대 확률보다 **같은 나이·성별 대비 상대 표현**을
  쓴다 (브리핑에 이미 그렇게 담겨 있다).
