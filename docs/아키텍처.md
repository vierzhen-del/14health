# 14health 아키텍처 — APK 검토 · 메뉴 트리 · 성능 · 외부 API

## 1. APK로 실행할 수 있나?

**현재 코드 그대로는 안 된다.** 백엔드가 Python(`http.server`)이라 안드로이드에서
그대로 돌지 않는다. 진짜 APK를 만들려면 약 1,400줄(`parse`·`recommend`·`analysis`·
`vault`·`calendar_index`·`relations`·`insurance`)을 JS로 포팅해야 한다.

**그런데 그럴 필요가 없다.** 사용자의 Galaxy Tab S9 Ultra는 이미 Termux + proot
(Ubuntu)로 n8n을 돌리는 홈서버다. 같은 proot에 `pip install -e .` 하면 끝이고,
vault를 Syncthing 폴더에 두면 폰·PC로 자동 복제된다.

| | proot 배포 (권장) | Capacitor APK |
|---|---|---|
| 코드 변경 | **없음** | Python ≈1,400줄 → JS |
| 옵시디안 vault 쓰기 | 이미 바인드됨 | SAF 권한 처리 필요 |
| 기기 간 동기화 | Syncthing 그대로 | 별도 구현 |
| n8n 연동 | 같은 proot — CLI 직접 호출 | HTTP 왕복 |
| 홈 화면 아이콘 | 브라우저 "홈 화면에 추가" | 진짜 앱 아이콘 |
| 완전 오프라인 | 서버가 떠 있어야 함 | 가능 |
| **Health Connect(걸음수·심박)** | **불가** | **가능** |

→ 설치 절차는 `tabs9-배포.md`. **APK는 Health Connect 데이터가 필요해지는
시점에 착수한다** (로드맵은 `APK-로드맵.md`).

## 2. 메뉴 트리

```
🏠 홈
   ├─ 💰 실비 미청구 배너 (건수·금액, 시효 임박 경고)
   └─ 구성원 카드 (표시명·나이 · 혈압/혈당/BMI 배지 · 추이 스파크라인)
        └─ 탭 → 구성원 상세

👨‍👩‍👧‍👦 가족
   ├─ 가족 관계도 — 세대별 배치, 처가는 점선, 노드에 주요 병명 배지
   │     조부모 세대 → 부모·처부모 세대 → 본인·배우자 → 자녀 → 손자녀
   ├─ 구성원 필터 칩
   └─ 상세: 수치 추이 차트(기준선) · 위험요인 · 권장검진 · 진료과 · 생활습관

✍️ 입력 — 6가지 방식
   ├─ 직접 입력 (검진 수치 / 진료 기록 / 가족력)
   ├─ 💬 대화 텍스트   "나 2025년 혈압 138/88 체중 80"
   ├─ 📷 사진          카메라 촬영 또는 갤러리 → 로컬 OCR → 가족 자동매칭
   ├─ 🗂 폴더 이미지    폴더 경로 지정 → 일괄 분석
   └─ 📄 MD 파일       옵시디안 노트면 바로 저장

📅 캘린더
   ├─ 연간 보기 — 12개월 그리드 (일자·구성원, 종류별 색상)
   ├─ 주차별 보기 — ISO 주차 목록 (날짜·구성원·진료과·진단)
   ├─ 연도 선택 · 구성원 필터(가족 전체/개인)
   └─ 항목 탭 → 옵시디안 노트 열기

🩺 추천
   ├─ 대상 선택(가족 전체/개인) → [추천 실행]
   ├─ 위험요인 · 권장검진+주기 · 분기별 계획 · 진료과 · 생활습관
   └─ 생애주기 검진 타임라인 (영유아기~노년기, 구성원 현재 위치)

⚙️ 설정
   ├─ 🗂 옵시디안 Vault — 경로 표시 · [Vault 생성] · [기존 Vault 연결]
   ├─ 👪 가족 관리 — 관계호칭·분류·표시명·**실명**(로컬 전용) 등록, 구성원 목록
   ├─ 🛡 보험 관리 — 보험사·상품·종류·보장항목 (**증권번호 저장 안 함**)
   ├─ 🧬 가족정보 JSON — 내보내기(실명 포함 선택) / 가져오기
   ├─ 📄 MD 내보내기 / 읽어오기
   ├─ 📤 Vault zip 내보내기 · 📥 가져오기
   └─ 최근 이력 · 노션 동기화(마스킹)
```

## 3. 성능 (실측)

**측정 조건**: 가족 11명 × 노트 **2,434개**(검진 220 + 진료 2,200 + 프로필/가족),
이 컨테이너 기준. 각 3회 중 최솟값.

| 항목 | 캐시 前 | 캐시 後 | 목표 |
|---|---:|---:|---:|
| `/api/data` (홈·가족 전체) | 1,746 ms | **67 ms** | <1,000 |
| `/api/calendar` (전체 인덱스) | 1,720 ms | **92 ms** | <300 |
| `/api/calendar?year=2025` | 1,728 ms | **61 ms** | <300 |
| `/api/tree` (관계도) | 1,555 ms | **61 ms** | <300 |
| `/api/claims` (실비 미청구) | 3 ms | **0 ms** | <300 |

**병목은 YAML frontmatter 파싱**이었다. `vault.read_note()`에 (경로 → mtime·size·
파싱결과) 캐시를 넣어 파일이 그대로면 재파싱하지 않게 했다 — **약 26배 개선**.

- 옵시디안이나 Syncthing이 바깥에서 파일을 고쳐도 mtime/size가 바뀌므로 자동 무효화된다
  (테스트로 고정).
- 호출자가 결과를 변형해도 캐시가 오염되지 않도록 복사본을 돌려준다.
- 탭 전환은 데이터를 이미 받아둔 상태에서 JS로만 계산하므로 네트워크 왕복이 없다.
- 사진 OCR은 tesseract 특성상 장당 2~5초 — 이건 캐시 대상이 아니다.

## 4. 외부 API 검토 결과

| API | 개인 사용 | 판정 근거 |
|---|---|---|
| **HIRA 병원·약국** | ✅ 즉시 가능 | data.go.kr 회원가입 + 활용신청으로 키 발급 |
| **NHIS 건강검진** | ⚠️ 본인 결과는 불가 | 공개된 건 *표본 100만명 통계셋*이지 개인 결과가 아님 |
| **마이헬스웨이** | ❌ 개인 불가 | 이용기관 사전심사 대상, 의료법 21~23조상 민간 전송 제한 |
| **Garmin Health** | ❌ 사실상 불가 | 파트너 승인 전용(self-serve 없음), 2026년 신규 접수 중단 |
| **Health Connect** | 🔶 APK 필요 | 온디바이스 API — 안드로이드 앱만 읽을 수 있음 |
| **MCP 서버화** | ✅ 가능 | Tab S9에 n8n-mcp가 이미 등록돼 있어 같은 방식으로 확장 |
| **n8n 자동화** | ✅ 가능 | Tab S9에서 이미 가동 중 |

**결론**: 개인 진료·검진 내역의 *자동* 연동은 제도적으로 막혀 있다. 그래서 이 앱의
**영수증 촬영 OCR + 수동 입력**이 우회가 아니라 현실적인 정공법이다. 여기에
사용자가 공단 사이트에서 **직접 내려받은 파일을 가져오는 경로**를 더하면
(인증은 사용자가 직접 하므로 앱이 인증정보를 만지지 않는다) 실질적으로 필요한
데이터는 대부분 확보된다.

### 구현된 연동

| 기능 | 명령 | 전송되는 값 |
|---|---|---|
| 병의원·약국 찾기 | `14health hospital --department 소아청소년과` | **지역·진료과·상호뿐** (화이트리스트로 강제, 테스트로 고정) |
| 공식 파일 가져오기 | `14health official <파일\|폴더>` | **전송 없음** — 사용자가 내려받은 파일을 로컬에서 파싱 |
| MCP 서버 | `14health mcp` (stdio) | 로컬 vault만. 예외는 `find_hospital` 하나 |
| n8n 워크플로우 | `docs/n8n-워크플로우.md` | Tab S9 로컬 실행, 알림은 마스킹 요약만 |

MCP가 노출하는 도구 9종: `list_members` · `member_summary` · `recommend` ·
`add_visit` · `add_checkup` · `calendar` · `pending_claims` · `find_hospital` ·
`family_tree`. Tab S9 등록:

```bash
claude mcp add 14health -- 14health mcp
```

심평원 키는 로컬 설정에만 둔다 — `14health config set hira_key <키>`.
키가 없으면 병원 찾기만 비활성되고 나머지 기능은 그대로 동작한다.

### 아직 남은 것

- **Health Connect**(걸음수·심박·수면)는 안드로이드 앱만 읽을 수 있어 APK가 필요하다.
  이 하나 때문에 APK를 만들 가치가 생기는 시점이 오면 `APK-로드맵.md` 를 따른다.

## 5. 개인정보 설계 요약

| 데이터 | 어디에 | 근거 |
|---|---|---|
| 수치·증상·처방·진단·분석 | 로컬 vault 노트 **only** | 앱의 1원칙 |
| 실명 | 로컬 config(`~/.config/14health/`, chmod 600) | 영수증 자동매칭에만 사용, vault엔 관계호칭만 |
| 증권번호·고객번호 | **저장 안 함** | 스키마에 필드가 없어 전달해도 버려짐 |
| 주민번호·전화·병원 등록번호 | 저장 전 마스킹 | `anonymize.py`, OCR 로마자 오독분도 포함 |
| 노션 | 마스킹 이력 5필드만 | 날짜·대상·작업유형·제목(수치 제거)·옵시디안 링크 |
| git | 아무것도 없음 | vault는 저장소 밖, `.gitignore` 이중 방어 |
| LAN 접속 | `--lan` 시에만, 1회용 토큰 필수 | 기본은 127.0.0.1 전용 |
